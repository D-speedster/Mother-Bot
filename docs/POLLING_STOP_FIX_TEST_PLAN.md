# تست پلن اصلاح توقف پولینگ ربات‌های فرزند

## خلاصه مشکل قبلی
وقتی `stop_bot()` صدا زده می‌شد، `task.cancel()` اجرا می‌شد اما حلقه پولینگ ربات فرزند همچنان به کار خود ادامه می‌داد و ربات خاموش نمی‌شد.

## اصلاحات اعمال شده

### 1. در متد `stop_bot()` در `services/runner.py`:
```python
# ⚠️ FIX: task را از dict برمی‌داریم (نه فقط get)
task = self._tasks.pop(bot_id, None)

# بررسی اینکه task قبلاً done نشده باشد
if task.done():
    return True

# کنسل کردن task
task.cancel()

# ⚠️ FIX: منتظر توقف کامل task بمانیم (با timeout)
try:
    await asyncio.wait_for(task, timeout=2.0)
except asyncio.CancelledError:
    # انتظار می‌رود - task کنسل شد
    logger.debug(f"✅ Task ربات {bot_id} کنسل شد")
except asyncio.TimeoutError:
    logger.warning(f"⚠️ Timeout در انتظار توقف ربات {bot_id}")
```

**تغییرات کلیدی:**
- استفاده از `.pop()` به جای `.get()` برای حذف فوری task از dictionary
- اضافه کردن `await asyncio.wait_for(task, timeout=2.0)` برای انتظار تا کنسل شدن کامل
- مدیریت صحیح `CancelledError` و `TimeoutError`

### 2. در متد `_run_bot_task()` در `services/runner.py`:
```python
try:
    await dp.start_polling(bot)
except asyncio.CancelledError:
    # ⚠️ CRITICAL: این exception باید raise شود
    logger.info(f"🛑 حلقه polling ربات {bot_id} کنسل شد")
    raise

# در بخش اصلی try-except:
except asyncio.CancelledError:
    # ⚠️ CRITICAL: دوباره raise می‌کنیم
    logger.info(f"🛑 تسک پولینگ ربات {bot_id} با موفقیت کنسل و متوقف شد")
    raise

# در finally block:
if bot:
    try:
        # ⚠️ FIX: بررسی اینکه session باز است
        if bot.session and not bot.session.closed:
            await bot.session.close()
            logger.debug(f"🔒 session ربات {bot_id} بسته شد")
    except Exception as e:
        logger.error(f"⚠️ خطا در بستن session ربات {bot_id}")
```

**تغییرات کلیدی:**
- Wrap کردن `dp.start_polling()` در try-except جداگانه برای catch کردن فوری `CancelledError`
- Raise کردن `CancelledError` در دو سطح (polling و task)
- بررسی `bot.session.closed` قبل از بستن session
- پاکسازی صحیح منابع در finally block

### 3. در handler‌های `handlers/bot_maker.py`:
- تابع `callback_delete_bot()`: صدا زدن `await bot_runner.stop_bot(bot_id)` قبل از حذف
- تابع `callback_toggle_bot_status()`: 
  - وقتی وضعیت به inactive تغییر می‌کند: صدا زدن `stop_bot()`
  - وقتی وضعیت به active تغییر می‌کند: صدا زدن `start_bot()`

## سناریوهای تست

### تست 1: توگل کردن ربات به حالت غیرفعال
**مراحل:**
1. ربات مادر را اجرا کنید: `python bot.py`
2. در تلگرام، یک ربات فرزند بسازید (اگر قبلاً ندارید)
3. وارد پنل مدیریت ربات شوید: "🤖 مدیریت ربات‌ها" → "📋 ربات‌های من"
4. روی ربات خود کلیک کنید
5. روی "⏸ توقف ربات" کلیک کنید

**نتیجه مورد انتظار:**
- در لاگ‌های ربات مادر، پیام زیر نمایش داده شود:
  ```
  🛑 در حال توقف ربات {bot_id}...
  🛑 حلقه polling ربات {bot_id} کنسل شد
  🛑 تسک پولینگ ربات {bot_id} با موفقیت کنسل و متوقف شد
  🔒 session ربات {bot_id} بسته شد
  🧹 task ربات {bot_id} از dict حذف شد
  ✅ ربات {bot_id} با موفقیت متوقف شد
  ```
- در UI تلگرام، پیام "⏸ ربات متوقف شد" نمایش داده شود
- اگر به ربات فرزند پیام بدهید، پاسخی دریافت نکنید (چون ربات آفلاین است)

### تست 2: توگل کردن ربات به حالت فعال
**مراحل:**
1. ربات را در تست قبل غیرفعال کرده‌اید
2. در پنل مدیریت، روی "▶️ فعال‌سازی ربات" کلیک کنید

**نتیجه مورد انتظار:**
- در لاگ‌های ربات مادر، پیام زیر نمایش داده شود:
  ```
  🚀 شروع ربات {bot_id} (type=...) برای کاربر ...
  ✅ ربات {bot_id} وارد حلقه polling شد
  ✅ ربات {bot_id} روشن شد
  ```
- در UI تلگرام، پیام "🟢 ربات الان آنلاین است" نمایش داده شود
- اگر به ربات فرزند `/start` بدهید، پاسخ دریافت کنید

### تست 3: حذف ربات در حین اجرا
**مراحل:**
1. مطمئن شوید ربات فرزند فعال و در حال اجراست
2. در پنل مدیریت، روی "🗑 حذف ربات" کلیک کنید
3. روی "✅ بله، حذف شود" کلیک کنید

**نتیجه مورد انتظار:**
- در لاگ‌های ربات مادر، پیام‌های زیر به ترتیب نمایش داده شوند:
  ```
  🛑 در حال توقف ربات {bot_id}...
  🛑 حلقه polling ربات {bot_id} کنسل شد
  🛑 تسک پولینگ ربات {bot_id} با موفقیت کنسل و متوقف شد
  🛑 ربات {bot_id} متوقف شد قبل از حذف
  ✅ ربات {bot_id} توسط کاربر ... حذف شد
  ```
- در UI تلگرام، پیام "✅ ربات با موفقیت حذف شد" نمایش داده شود
- ربات از لیست ربات‌های شما حذف شود

### تست 4: توقف چندین ربات همزمان
**مراحل:**
1. چند ربات فرزند بسازید (حداقل 2-3 عدد)
2. همه را فعال کنید
3. به سرعت همه را غیرفعال کنید (یکی پس از دیگری)

**نتیجه مورد انتظار:**
- هر ربات به‌درستی متوقف شود
- هیچ `RuntimeError` یا `CancelledError` handle نشده رخ ندهد
- لاگ‌ها برای هر ربات به صورت مجزا نمایش داده شوند

### تست 5: ری‌استارت ربات مادر با ربات‌های فعال
**مراحل:**
1. چند ربات فرزند بسازید و فعال کنید
2. ربات مادر را stop کنید (Ctrl+C)
3. ربات مادر را دوباره start کنید: `python bot.py`

**نتیجه مورد انتظار:**
- در startup، لاگ زیر نمایش داده شود:
  ```
  📋 شروع راه‌اندازی X ربات فعال در استارت‌آپ...
  🚀 شروع سیستمی ربات ... (type=...) برای کاربر ...
  ✅ ربات ... (@username) شروع شد (1/X)
  ...
  🎉 استارت‌آپ کامل شد: X/X ربات فرزند با موفقیت روشن شدند
  ```
- همه ربات‌های فعال به صورت خودکار start شوند
- همه ربات‌های فرزند به پیام‌ها پاسخ دهند

## نتیجه‌گیری

با اعمال این اصلاحات:

1. **مدیریت صحیح CancelledError**: Exception به‌درستی raise و handle می‌شود
2. **حذف فوری از Dictionary**: استفاده از `.pop()` به جای `.get()`
3. **انتظار برای کنسل شدن کامل**: استفاده از `asyncio.wait_for()` با timeout
4. **پاکسازی صحیح منابع**: بستن session و حذف task در finally block
5. **عدم تداخل Router**: هر ربات Router اختصاصی خود را دارد
6. **عدم تداخل Webhook**: پاک کردن webhook قبل از polling

این تغییرات باعث می‌شود که:
- ربات‌های فرزند بلافاصله پس از توگل یا حذف متوقف شوند
- هیچ memory leak یا resource leak رخ ندهد
- سیستم stable و قابل اعتماد باشد
