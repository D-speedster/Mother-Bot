## ویژگی‌های پیاده‌سازی شده

### ✅ جدول دیتابیس
```sql
CREATE TABLE deposit_requests (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    amount INTEGER NOT NULL,
    receipt_photo_id TEXT,           -- شناسه عکس در تلگرام
    tracking_code TEXT,               -- شماره پیگیری
    status TEXT NOT NULL DEFAULT 'pending',  -- pending, approved, rejected
    admin_note TEXT,                  -- یادداشت ادمین
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL,
    FOREIGN KEY (user_id) REFERENCES users(user_id) ON DELETE CASCADE
)
```

### ✅ سرویس مدیریت درخواست‌ها (`services/deposit_service.py`)
```python
class DepositService:
    async def create_deposit_request()  # ثبت درخواست جدید
    async def get_pending_requests()    # دریافت درخواست‌های pending
    async def get_request_by_id()       # دریافت یک درخواست خاص
    async def approve_request()         # تأیید درخواست
    async def reject_request()          # رد درخواست
    async def get_user_requests()       # درخواست‌های یک کاربر
```

## جریان کاربر (User Flow)

### مرحله 1: ورود به بخش شارژ
```
کاربر → "💳 کیف پول من" → "💰 شارژ کیف پول"
```

**نمایش داده می‌شود:**
- اطلاعات کارت بانکی (شماره کارت، نام صاحب کارت، نام بانک)
- شناسه کاربری
- راهنمای شارژ
- دکمه "📤 ثبت فیش واریزی"

### مرحله 2: ثبت فیش
```
کاربر → "📤 ثبت فیش واریزی"
```

**ربات می‌پرسد:**
- مبلغ واریزی (به تومان)

**Validation:**
- مبلغ باید عدد باشد
- مبلغ باید بزرگتر از 0 باشد
- مبلغ باید حداقل 10,000 تومان باشد

### مرحله 3: ارسال فیش/کد پیگیری
```
کاربر می‌تواند یکی از موارد زیر را ارسال کند:
  1. تصویر فیش واریزی (Photo)
  2. شماره پیگیری (Text)
```

**پس از ارسال:**
- درخواست در دیتابیس با وضعیت `pending` ثبت می‌شود
- شماره درخواست (request_id) به کاربر داده می‌شود
- پیام تأیید نمایش داده می‌شود
- اعلان به ادمین ارسال می‌شود

### مرحله 4: انتظار برای تأیید
کاربر پیام زیر را دریافت می‌کند:
```
✅ فیش شما با موفقیت ثبت شد!

🆔 شماره درخواست: 123
💰 مبلغ: 100,000 تومان

📋 وضعیت: در انتظار بررسی ادمین

⏱️ زمان تقریبی بررسی: حداکثر 2 ساعت
```

### مرحله 5: دریافت نتیجه
**اگر تأیید شود:**
```
✅ کیف پول شما شارژ شد!

💰 مبلغ: 100,000 تومان
🆔 شماره درخواست: 123

موجودی جدید شما در بخش "💳 کیف پول من" قابل مشاهده است.
```

**اگر رد شود:**
```
❌ درخواست شارژ شما رد شد

💰 مبلغ: 100,000 تومان
🆔 شماره درخواست: 123

⚠️ دلایل احتمالی:
• عدم انطباق مبلغ واریزی
• عدم تطابق اطلاعات
• فیش نامعتبر
```

## جریان ادمین (Admin Flow)

### مرحله 1: دریافت اعلان
ادمین پیام زیر را دریافت می‌کند:
```
🔔 درخواست شارژ جدید

🆔 شماره درخواست: 123
👤 کاربر: 79049016
💰 مبلغ: 100,000 تومان
🔢 شماره پیگیری: 1234567890 (اگر وجود داشته باشد)
```

**همراه با:**
- تصویر فیش (اگر ارسال شده باشد)
- دو دکمه: "✅ تأیید و شارژ" و "❌ رد فیش"

### مرحله 2: تأیید درخواست
```
ادمین → "✅ تأیید و شارژ"
```

**عملیات انجام شده:**
1. وضعیت درخواست به `approved` تغییر می‌کند
2. `wallet_service.add_credit()` صدا زده می‌شود
3. موجودی کاربر افزایش می‌یابد
4. تراکنش در جدول `transactions` ثبت می‌شود
5. پیام تأیید به کاربر ارسال می‌شود
6. پیام ادمین آپدیت می‌شود

### مرحله 3: رد درخواست
```
ادمین → "❌ رد فیش"
```

**عملیات انجام شده:**
1. وضعیت درخواست به `rejected` تغییر می‌کند
2. پیام رد به کاربر ارسال می‌شود
3. پیام ادمین آپدیت می‌شود
4. هیچ تغییری در موجودی کاربر رخ نمی‌دهد

## امنیت و Validation

### ✅ بررسی‌های انجام شده:

#### در دریافت مبلغ:
- مبلغ باید عدد باشد
- مبلغ باید > 0 باشد
- مبلغ باید >= 10,000 تومان باشد

#### در ثبت درخواست:
- حداقل یکی از فیش یا کد پیگیری باید وجود داشته باشد
- user_id باید معتبر باشد

#### در تأیید/رد:
- فقط ادمین‌های لیست `ADMIN_USER_IDS` دسترسی دارند
- درخواست باید در وضعیت `pending` باشد
- جلوگیری از تأیید/رد مجدد

### ✅ Transaction Safety:
- کل فرآیند تأیید atomic است
- اگر خطایی رخ دهد، rollback می‌شود
- تراکنش فقط در صورت موفقیت کامل ثبت می‌شود

## خطایابی (Troubleshooting)

### مشکل: ادمین اعلان دریافت نمی‌کند
**راه‌حل:**
- مطمئن شوید آیدی ادمین در `ADMIN_USER_IDS` است
- بررسی کنید که ربات قبلاً با ادمین صحبت کرده باشد
- لاگ‌های ربات را بررسی کنید

### مشکل: عکس فیش ارسال نمی‌شود
**راه‌حل:**
- مطمئن شوید عکس به صورت Photo ارسال می‌شود (نه Document)
- اندازه عکس نباید بیش از حد مجاز تلگرام باشد

### مشکل: موجودی شارژ نمی‌شود
**راه‌حل:**
- بررسی کنید درخواست تأیید شده باشد
- لاگ‌های ربات را بررسی کنید
- بررسی کنید `wallet_service` به درستی کار می‌کند
